# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive sumi-e reading of the Mumonkan (The Gateless Gate) in the browser: all 49 koan cases staged as small low-poly ink-painting dioramas, with text, narration, ambience, and a meditation timer. It is an **interactive book, not a game** — dioramas are ambient scenes; touch responses are optional delights, never gates.

The design doc at `docs/gateless-gate-design-doc.md` is authoritative; its dated revision notes **override** anything they contradict elsewhere in the doc. Milestone plans/specs live in `docs/superpowers/`. **`docs/` is gitignored**, like `local/` — it is the working record, not part of the published repo, so a fresh clone will not have it and nothing that ships may depend on it.

## Commands

- Run: `npm start` (`npx -y http-server -p 8105 -c-1 .`) then visit http://localhost:8105 — **no build step**; ES modules are served directly and Three.js is vendored in `lib/` (version in `lib/THREE_VERSION.txt`).
- Test all: `npm test` (runs `node --test` over `tests/`, Node 20+)
- Test one file: `node --test tests/k29.test.js`
- Regenerate the whole-book Markdown at the repo root: `npm run book` (`node scripts/build-book.js`) — writes `THE-GATELESS-GATE.md` from the generated text modules, so run `build-text.js` first if the source changed. `tests/book-md.test.js` fails if the committed file is stale.
- Regenerate the text modules after editing `book/gateless-gate.md`: `node scripts/build-text.js` (writes both `src/koans/text/mumonkan.js` and `matter.js`). **The whole book is that one checked-in Markdown file** — the preface, the forty-nine, the afterword: `##` opens a page, `###` opens a section, and section headings are matched **exactly**, because a heading chooses the key that names the baked narration file and a retitled heading would otherwise orphan an mp3. Inside a section a blank line is a paragraph or stanza break; within a paragraph, prose line breaks are wrapping and rejoin with a space, verse line breaks are the verse and are kept. `scripts/lib/parse-book.js` holds the manifest saying which sections are which — that table replaced the U+3000 ideographic space the old matter source marked verse with. `book/translation-notes.md` beside it is the scholarly record behind the new front-and-back-matter translation (Chinese, Taishō citations, unresolved readings); nothing builds from it, and the four pieces that ship point at the book file rather than repeating it.
- Re-bake narration after a text change: `node scripts/build-narration.js` — only units whose text/voice/preset hash changed are regenerated, so this is normally a few files and a few cents. Needs a Gemini key in `local/gemini-key.txt` or `GEMINI_API_KEY` (the live provider is Gemini — see `PROVIDER` in `scripts/lib/narration-voice.js`; the OpenAI path remains for the audition bake-off). `--dry-run` shows what would bake without spending; `--case N` — or a matter-page slug such as `preface` — scopes it, and an unrecognised value is a hard error, never a silent fall-through to baking the whole book. Voice and delivery live in `scripts/lib/narration-voice.js`; `scripts/narration-audition.js` is the bake-off for changing them.
- Audit a bake for bad takes (no API cost): `node scripts/check-narration.js` (duration vs character count) and `node scripts/check-narration-wps.js` (speaking pace, crediting pauses). They normalise differently, so run both. Neither catches a same-length garble — that still needs ears.
- Screenshots while the preview panel is hidden: `node scripts/dev/shot-server.js` (port 8106; workspace launch config `gate-shots`), then POST a `canvas.toDataURL(...)` string to `http://localhost:8106/<name>` — files land in `shots/` (gitignored).

`local/` is gitignored — it holds the source text and the author's local notes; don't assume its contents exist in a fresh clone.

## Headless driving

`window.gate` exposes hooks for driving the app without a visible page: `step(n)`, `state()`, `enter(slug)`, `exit()`, `menu(open?)`, `skipIntro()`, `dissolve('in'|'out', s?)`, `sit(min)`, `endSit()`, `markRead(slug)`, `markSat(slug)`, `setSound(on)`, `look(on?)`, `readAloud()`, `auto(on?)`. `state().reading` reports `{ look, all, slug }` — `look` is the text-aside view, `all` whether the page is being read aloud. The look never starts a reading, and a reading stops at the end of its own page rather than turning over.

Caveat: the hidden preview panel pauses `requestAnimationFrame`, so `await gate.enter(...)` hangs — dissolves only advance inside `step()`. Fire the call, then `step(60)` once per await stage (`loadKoan` → dissolveOut → dissolveIn), yielding between batches so microtasks flush.

## Architecture

- **Determinism rule:** seeded noise everywhere (`src/util/noise.js`), **no `Math.random` outside `src/audio/**`** — same steps, same state. Audio is exempt because noise buffers don't affect sim state.
- **Koan modules** (`src/koans/kN.js`): each default-exports `{ id, slug, title, accent, tier, text, ambience, mood?, camera?, build(ctx) }`. `build` returns `{ scene, update(dt, simTime), dispose(), fragment(), setCamera(), onEnter?(), onExit?() }`. **Ambience is `main.js`'s job**: the module's `ambience` recipe (and `mood`) is the single source of truth, started on enter and stopped on exit centrally — koans never call `startAmbience`/`stopAmbience` themselves. `registry.js` lazy-loads staged cases (`default-case.js` is the still-tested safety net). All 49 cases are staged; case 49 (Amban's addendum) is the closing "book at rest" scene, sealed by the same red torii the intro opens on. Case text comes from the generated `src/koans/text/mumonkan.js` — never hand-edit it; edit `book/gateless-gate.md` and rebuild.
- **The spine** (`src/spine.js`): the reading order — preface, the forty-nine in id order, afterword — as a list of slugs. `neighborSlug` walks it for paging and the arrow keys and **stops at both ends**; `loopNextSlug` beside it wraps afterword → preface, but it exists ONLY for auto mode (below) — the arrows never wrap. **Matter pages** (`src/koans/matter/preface.js`, `afterword.js`) are koan-shaped modules with `id: null` (no numeral seal). The **preface stages its own diorama** — the arriving road forks into two arms ("thousands of roads enter it"), a bonshō and a flag stand either side of the split, and no gate exists anywhere in it (tests/matter.test.js pins the fork). The **afterword** renders `buildHub()` — the title screen's world — with its own `SEEDS` so the two hub scenes are different land; the title screen's are fixed by the intro dolly (`intro_rails.js`). The afterword *derives* its Buddha's tree from `built.trees` rather than storing a coordinate — a stored copy once went stale when a seed changed and the meditator sat in open grass with nothing failing. `node scripts/dev/hub-trees.js` prints both hub scenes' trees. Matter text is generated into its **own module**, `src/koans/text/matter.js`, from the Preface and Afterword pages of `book/gateless-gate.md` — separate from `mumonkan.js` so that a preface edit can never rehash the 147 case bakes; the matter pages' own seven units (keyed by slug, e.g. `preface:verse`) bring the narration to 154. Both modules come out of one source and one parser, but they stay two files for that reason.
- **The look** (the eye in the stage toolbar, `main.js`): the text panel steps aside, the diorama takes the whole window, the camera drifts. **The camera controls belong to the look and nowhere else** (`canDragCamera` in `main.js`): reading a page you get the framing the case was composed for, breathing with the cursor parallax and nothing more — no drag, no wheel, and the wheel is not `preventDefault`ed so it falls through. In the look, drag and wheel are yours, and the drift gives way **for good** the first time you take hold (`taken` in `camera.js`) — it never takes the shot back, because a timed hand-back slid a just-framed composition away while you watched it. A page turn builds a fresh rig, so the next scene breathes again. Dev mode is **not** an exemption on a case (it was, and it meant the one person reading in dev mode never saw the reader's behaviour), and neither is the Contents (it was, so `MENU_CAM` could be aimed by dragging — and one screen swinging under the cursor while every other page held its shot read as a bug). `MENU_CAM` is aimed with the Compose panel's **sliders** instead, which drive the rig directly and never needed drag. A *view*, not a mode — the reader stays on their page — and it starts no narration. The `.gg-look-bar` (top-left) carries the look's own controls — leave, back, forward, read aloud — and greys out what cannot act rather than hiding it. **A read-aloud always ends at the end of its page** and never turns over. **Auto mode is the one deliberate exception**: the look bar's labelled switch ("Read the whole book, page after page") reads, pauses a few seconds, turns, and reads on — wrapping via `loopNextSlug` until switched off. A different promise made by a different, labelled switch; the read-aloud rule stands. The title card (`page_card.js`) shows only in the look, only on a page turn or a reading starting. `stageOnly()` derives layout from the look *or* a sit, so leaving a sit never yanks the panel back over the look.
- **The kit** (`src/kit/`): procedural builders (monk, gate, flag, quadruped, lantern…) shared by all cases. `plantTree(scene, { x, z, kind, height })` is the hand-placement shortcut beside `composeWorld`'s scatter: it samples the terrain for you (the y is what hand-placed trees got wrong), seeds the rotation from the position, and deliberately does no keepout work — it is the override. `bakeStatic(prop | props[], { name, into, keep })` merges a **still** prop down to one mesh per material — the counterpart to `plantTree`'s "this is the override": here the override is "nothing in this thing will ever move again." It must run **after** the case has finished posing, recolouring and composing — merging a part before its final pose or colour bakes in the wrong one, with nothing left afterward to fix it on. The single form mutates the prop in place and returns it, so `horse.group` stays the same object the case's `update` writes to; the array form merges several props into one new group and is where the large savings are (k45's eight figures were 68 draws and are now 2). It refuses geometry that carries anything past position and normal (foliage wind), invisible hit proxies, and instanced fields; `keep: ['tail']` excludes a named subtree for a prop that is still except for one part. The cost is that a baked prop is **opaque** — `getObjectByName('staff')` finds nothing — so the six cases that reach inside a figure (k3, k11, k15, k17, k32, k36) leave those particular figures unbaked. The hazard is broader than lookup-by-name: anything that finds a part by TRAVERSAL breaks too — `collectChimes` (`src/kit/chimes.js`) finds a hung fūrin by sweeping for `userData.hungBy === 'hangChimes'` on a group, so baking a `makeHut`/`makeGate` prop that hangs one deletes that group and the chime goes silent with nothing failing. `userData.bakedFrom` records the names of the props a merged group consumed, which is how a test still counts eight monks in a scene that draws one mesh. **Koan modules import the kit through `src/kit/index.js` and never from an individual kit file** — the facade is the one import surface, so a builder can move between files without touching a case. A symbol missing from `index.js` is a gap in the facade to fill, not a reason to reach past it. The reuse rule is absolute — behaviors (hover ruffle, bell strike) live **in the kit components**, not in individual cases. `makeHut`/`makeGate` take `chimes: <seed>` (0 = none) and hang one or two fūrin under the eave themselves; they sound without wiring because `main.js` hands `setChimeAudio` the app's one engine at startup, resolved at strike time so build order cannot mute them. **A piece whose whole behaviour is self-contained answers wherever it stands**, on that same pattern: a marker in `userData`, a `collect*` sweep main.js runs once per scene, and one central tap. Hung chimes work this way and so do drums (`collectDrums`/`beatDrumAt`/`setDrumAudio` in `kit/drum.js`) — a per-case tap left one of the book's two drums as scenery that swallowed every touch. Bells stay case-wired **because a bell strike is not self-contained**: case 16 turns a monk toward the sound, and a central handler has nowhere to put that. Note the ordering — main's taps are registered before the case's and *every* callback fires (a tap is never "consumed"), so a central handler must not overlap a case's own pick volumes. Scene assembly goes through `composeWorld` (ground + mountains + forest + seeded scatter with keepouts). Prefer keepouts by live reference — `{ at: object, r }` — over copied coordinates: a moved prop once left its keepout guarding empty grass with nothing failing. A case also hands `composeWorld` its own `view: CAM` (the same object its `camera:` names, hoisted to a const): `seenFrom` then refuses scatter positions no reachable heading can see, and because the placement loop retries, the same tree budget lands where it shows. **The meadow's reach and taper** are two workbench sliders (`setGrassReach`/`setGrassTaper` in `grassfield.js`, the same module-state idiom as `setGrassPatchiness`) — how far the field goes, and what fraction of that is solid before it dissolves. It dissolves in *both* density and plant size (`rim` on every placement, `RIM_SHRINK` in each renderer): thinning alone leaves full-height plants scattered along the boundary, which is what draws the edge. The plant budget scales with `grassArea(radius, taper)`, not with πr² — the two knobs pull against each other, so scaling on raw area silently moves the near-field density. **How windy a case is** is three `composeWorld` options — `grassWind` (amplitude: leans further, never faster), `grassGustScale` (a frequency, like its slider: **lower** is a broader gust), `grassGustSpeed` (world-units/sec the gusts travel — the knob that makes wind visibly cross the meadow). Each is **the same number its workbench slider reads** ("Grass wind" / "Gust patch" / "Gust drift"), not a multiplier, so a value found by dragging is the value typed into the case; `null` (the default) means "follow the slider", as every case did before these existed. They're recorded on the field as `caseWind`/`caseGustScale`/`caseGustSpeed`, and a pinned case **moves the sliders** on arrival rather than the sliders overwriting it: `debug.apply()` runs on every page build in every mode, so a bare assignment erased a case's weather on the frame its field was born, which is why none of this could be per-case at all. Grass only — a chime's liveliness is its own `setWindLevel()` and the audible wind is the ambience recipe's `wind:` token.
- **Shared helpers — use them, don't re-declare:** `src/util/math.js` (`clamp01`, `clamp`, `smoothstep`); `tapMeshes` in `src/kit/pick.js` for collecting tappable meshes; `wrapPi`/`bearing` exported beside `faceMonk` in `src/kit/monk.js` (the facing convention: bodies front local +z, a heading ψ points along `(sin ψ, cos ψ)` — hand-rolled variants have shipped quarter-turn bugs); tests build their ctx from `tests/helpers/fake-ctx.js`, and their probe cameras from `tests/helpers/rig-camera.js`. **A `camera:` block speaks heading and pitch in DEGREES** — `heading` 0 is square in front (+z), positive swings left; `pitch` 0 is level with the target, positive looks down on it — the same numbers the workbench's Compose panel shows, so a shot read off the sliders is the shot typed into the file. The old `azimuth`/`polar` radians are gone (`minPitch`/`maxPitch` replace `minPolar`/`maxPolar`, and read the opposite way round: a high lens is a high pitch). `eyePosition` in `src/camera.js` is the only place the spherical trig lives. In `update(dt, simTime)`, guard before simTime reaches any transform: `clock = Number.isFinite(simTime) ? simTime : clock + (dt || 0)`.
- **Comments are records** here — they carry decisions and past bugs so the same mistake is not made twice. Four rules keep them from becoming a second, rotting copy of the code:
  - **State the finding, not who said it.** No names, no quoted feedback, no dated audit chronology — "the chimes read as frozen" outlives "X said it looks frozen", and stays useful once the reason matters more than the meeting.
  - **Never restate a value that lives in the code beside you.** Say what a number achieves and what bounds it, not what it equals; a comment quoting `0.65` is a second definition that silently goes stale. Sweep tables and step-by-step arithmetic go the same way — keep the derivation's *shape* and point at where the inputs actually live.
  - **Keep what prevents a regression**: contracts, units, invariants, the non-obvious why, and the wrong turn that looks right on paper. Drop the narrative of superseded attempts once the lesson is stated.
  - **When retuning a number by hand, update the prose that presents it as solved or derived** — a cleanup pass found six kit headers contradicting their own code after "tweaks" commits did exactly this.
- **Render** (`src/render/`): the depth-edge ink pass in `post.js` is the only edge system — a Sobel over linear depth run as a post pass, not a second scene render or a per-mesh shell. Every lit surface is a `THREE.MeshLambertMaterial`, built by `washMaterial()` in `src/render/material.js`; there is no rebuild between what the kit builds and what renders, and no `toon`/`plainMaterial` split left to keep in sync — what a case authors is what ships. `makeLights` (key + hemisphere fill) lives in `src/render/lights.js`. **Where the key stands is per-case**, named as `sun: { heading, pitch }` in the same degrees-vocabulary as the `camera:` block (heading 0 square in front on +z, pitch above the focus) and read live by the workbench's "Sun heading"/"Sun height" sliders, which a case's aim **moves on arrival** the way a pinned `grassWind` moves its slider. What kind of light it is comes from the aim *relative to the case's own camera heading*: a small difference is frontal and flat, a quarter turn rakes, a half turn is contre-jour with the shadows running toward the reader. The key's height above the focus is fixed and pitch moves it **out**, not down — the shadow camera's near plane clips anything standing above the light, and a tree that loses its shadow that way fails silently. Case 19 is the one case that owns its light outright (it tracks its own moon) and clears `sun.userData.aim` to say so. Fog-to-paper, the post spine (`post.js`), ink dissolve for every transition (`dissolve.js`), and `freeze.js` holding the outgoing frame during cuts are all unchanged. **The reading light reaches the sky** (`nightsky.js`): with the page dark, the paper the diorama is painted on goes dark too and *nothing else does* — no light moves, so every lit surface keeps its value. The sky and the fog are separate depths and the fog goes much the shorter way (fog reaches everything far away, so taking it down with the sky darkens the receding ground and reads as a re-lighting; its small share exists only to close the pale band the split would otherwise draw along the horizon). A case's own page colour is the base rather than a replacement, so cases 27 and 28 keep their tint after dark; those two animate their sky and must lerp from `pageBase`/`fogBase`, never the palette constant. `main.js` hangs one shared `makeStars` field (`kit/stars.js` — a thousand points in one draw, shell riding the lens so nothing clips or parallaxes) over every page after dark; it is reparented on a page turn, never rebuilt, and must come off the outgoing scene before `buildKoan` disposes it. Case 28 used to reveal a star field of its own as the candle went out and no longer does — the sky is the reading light's everywhere. Shadows: real shadow maps ARE the shipped look since v6 (`shadows` defaults true in the workbench; `makeLights` carries the sun's shadow camera — ±15 frustum, 3072 map, ~100 texels/unit). The per-case `makeBlobShadow` washes were the original design; they were removed entirely once the maps shipped — every scene was building washes the workbench immediately hid.
- **Audio** (`src/audio/`): ambience and bells are fully procedural Web Audio, no samples. Pure **param tables** are unit-tested; node builders are browser-only. Recipes may flavor the wind (`wind:0.18:pine`), name a `rain` layer (case 34), or carry a `snow` token that swaps the reverb to the darker snow room (case 41). **Narration is the one exception to "no samples"** — all 154 sections are pre-baked mp3, played through an `<audio>` element outside the Web Audio graph (which is why `audio.duck()` ducks only the ambience bed). Runtime lookup is manifest-driven and degrades to silence: a partial bake is a safe state, never a stuck highlight.
- **Spatial audio** (`src/audio/spatial.js`): pure `spatialFor(source, listener)` returns `{ d, pan, gain, tone, wet }`; browser-only `makeSpatialBus` wires the nodes. The camera is the listener via `src/camera_listener.js` (plain vectors — `engine.js` never imports THREE). Every one-shot takes an optional `at`. **The trap worth knowing:** `.position` on an object nested under a group is a LOCAL position — finite, plausible, and wrong; use `getWorldPosition` into a module-level scratch `Vector3`. `voicesDry`/`voicesWet` carry diorama one-shots so `hushVoices()` can close them at a page turn; the sit bell, narration's chimes, and the drift layer's far bell deliberately route around that pair — they belong to the reader or the book, not the scene. Hidden pages pause on `visibilitychange`, never `blur` (alt-tabbing must not silence a page still on screen); a running sitting suppresses the pause so the closing bell rings on time.
- **Routing** (`src/router.js`): deep links, one invariant — **the URL always names what's on screen**. `parseRoute`/`hashFor` are pure and Node-testable; `makeRouter` is the browser half, wired into five points in `main.js`. Anything that calls `enter`/`exit` or changes `mode` must keep the URL in sync.
- **The staging net** (`tests/staging.test.js`): builds *every* staged case and holds all of them to the module contract at once — shape, no non-finite transforms, taps safe before `setCamera` and with no audio engine, finite-scalar fragments, the <150 draw budget, the accent in its home frame, and that every interaction reaches the audio engine. A new case is covered automatically. Deliberate deviations are named constants at the top of that file with their reasons — read those before "fixing" one. Bespoke per-case tests remain the right tool for cases with real logic.
- **Testable-state pattern:** logic that tests need is split from DOM/WebGL glue — `menu_state.js` vs `menu.js`, `scroll_state.js` vs `scroll.js`, param tables vs node builders. Tests run in plain Node with no browser; keep new logic on the testable side of that line.
- **Layout guides** (`src/dev/overlay.js`): the workbench's "Layout guides" switch draws a scene's invisible half — keepout circles (prop and grass), mountain footprints, the scatter ring, a stem on everything placed, and the camera's orbit target. `composeWorld` leaves the record on `scene.userData.layout` (data only, no meshes); `layoutGuides()` is the pure half and `makeLayoutOverlay()` the THREE half. Everything it draws is **lines, never meshes** (which is what keeps a guide off the shadow map — nothing in the render path sets `castShadow` on anything but a mesh) and every guide material sets **`depthWrite: false`** besides, which is what actually keeps a guide out of the surviving ink pass: that pass is a Sobel over the depth buffer and does not care whether a draw was a line or a mesh.
- **Look-dev harnesses:** `dev/kit-preview.html` iterates on art and kit pieces in isolation. `dev/model-viewer.html` is the standalone viewer — every kit model, gallery grid, per-model notes, hot reload (~1s) — rendering the **shipped** shading plus its own two dim fill lights (L to toggle); `dev/model-shot.html?mode=lit` matches it. The roster lives in `src/modelviewer/roster.js`, shared with `model-shot.html`: register a new kit model ONCE there and viewer and `shot.js --model` both pick it up. `dev/bell-audition.html` does the same for the bonshō (live macros over the three shipped presets; "print all three presets" dumps pasteable `ampMult` arrays); `dev/hanging-audition.html` for the hanging chimes. Details and known gaps live in each file's own header comments.

## Style guardrails (from the design doc)

- One accent hue per koan against monochrome ink + paper; fog dissolves everything before any horizon.
- **Nothing lit is painted at `INK`.** The book shades through plain Lambert, which has no fixed bands to quote a level from — a surface takes a continuous value that depends on its normal against the key light, not a multiplier — but an INK-coloured lit surface still renders at roughly its own value times the irradiance, which is still far too dark to read as anything but a hole. Lit surfaces take `INK_LIT` (`wash(0.80)`, still the darkest paint in the book, just paint rather than a hole in the page); raw `INK` is reserved for genuine voids — a cave throat, a doorway at night — drawn unlit with `MeshBasicMaterial`, where there is no shading to lose. See `src/palette.js`'s own comment on `INK_LIT` for the fuller argument, including what the toon-ramp-era arithmetic this rule used to quote has and has not been re-derived for.
- Audio is minimal and chill: no singing bowl, no crickets. Bells, wind, quiet knocks are the palette. Nothing loud by default.
- Sensitive cases (3, 5, 14, 41) are handled through ink metaphor, never literal harm.
- Budgets: < 150 draw calls per scene, whole app ~1.5 MB gzipped, no downloaded assets. The baked narration (~35 MB of mp3, all 154 units) sits outside this budget: lazy-loaded per case, never bundled.
