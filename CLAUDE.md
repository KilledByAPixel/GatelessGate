# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive sumi-e reading of the Mumonkan (The Gateless Gate) in the browser: all 49 koan cases staged as small low-poly ink-painting dioramas, with text, narration, ambience, and a meditation timer. It is an **interactive book, not a game** — dioramas are ambient scenes; touch responses are optional delights, never gates.

The design doc at `docs/gateless-gate-design-doc.md` is authoritative; its dated revision notes **override** anything they contradict elsewhere in the doc. Milestone plans/specs live in `docs/superpowers/`.

## Commands

- Run: `npx -y http-server -p 8105 -c-1 .` then visit http://localhost:8105 — **no build step**; ES modules are served directly and Three.js is vendored in `lib/` (version in `lib/THREE_VERSION.txt`).
- Test all: `npm test` (runs `node --test` over `tests/`, Node 20+)
- Test one file: `node --test tests/k29.test.js`
- Regenerate the whole-book Markdown at the repo root: `npm run book` (`node scripts/build-book.js`) — writes `THE-GATELESS-GATE.md` from the generated text modules, so run `build-text.js` first if the source changed. `tests/book-md.test.js` fails if the committed file is stale, which is what stops it drifting from the reading.
- Regenerate koan text after editing `local/gateless-gate.txt`: `node scripts/build-text.js` (writes `src/koans/text/mumonkan.js`; the same run also parses `local/mumonkan-front-and-back-matter.md` into `src/koans/text/matter.js` and exits 1 if that second file is missing — it's required, not optional)
- Re-bake narration after a text change: `node scripts/build-narration.js` — only units whose text/voice/preset hash changed are regenerated, so this is normally a few files and a few cents. Needs a Gemini key in `local/gemini-key.txt` or `GEMINI_API_KEY` (the live provider is Gemini — see `PROVIDER` in `scripts/lib/narration-voice.js`; the OpenAI path still exists for the audition bake-off and reads its own key the same way). Use `--dry-run` to see what would bake without spending anything, and `--case N` — or a matter-page slug such as `preface` — to scope it; an unrecognised value is a hard error, not a silent no-op, since it must never fall through to baking the whole book. Voice and delivery live in `scripts/lib/narration-voice.js`; `scripts/narration-audition.js` is the bake-off for changing them.
- Audit a bake for bad takes (no API cost): `node scripts/check-narration.js` fits duration vs character count; `node scripts/check-narration-wps.js` measures words-per-second speaking pace after crediting paragraph-break and lead-in pauses. Both flag dropouts (too short/fast) and repeats or dead air (too long/slow) by comparing each unit to its section; they normalise differently, so run both. Neither can catch a same-length garble — that still needs ears.
- Screenshots while the preview panel is hidden: `node scripts/dev/shot-server.js` (port 8106; workspace launch config `gate-shots`), then POST a `canvas.toDataURL(...)` string to `http://localhost:8106/<name>` — files land in `shots/` (gitignored)

`local/` is gitignored — it holds the source text and Frank's local notes; don't assume its contents exist in a fresh clone.

## Headless driving

`window.gate` exposes hooks for driving the app without a visible page: `step(n)`, `state()`, `enter(slug)`, `exit()`, `menu(open?)`, `skipIntro()`, `dissolve('in'|'out', s?)`, `sit(min)`, `endSit()`, `markRead(slug)`, `markSat(slug)`, `setSound(on)`, `look(on?)`, `readAloud()`. `state().reading` reports `{ look, all, slug }` — `look` is the text-aside view, `all` whether the page is being read aloud. The two are independent: the look never starts a reading, and a reading stops at the end of its own page rather than turning over.

Caveat: the hidden preview panel pauses `requestAnimationFrame`, so `await gate.enter(...)` hangs — dissolves only advance inside `step()`. Fire the call, then `step(60)` once per await stage (`loadKoan` → dissolveOut → dissolveIn), yielding between batches so microtasks flush.

## Architecture

- **Determinism rule:** seeded noise everywhere (`src/util/noise.js`), **no `Math.random` outside `src/audio/**`** — same steps, same state. Audio is exempt because noise buffers don't affect sim state.
- **Koan modules** (`src/koans/kN.js`): each default-exports `{ id, slug, title, accent, tier, text, ambience, mood?, build(ctx) }`. `build` returns `{ update(dt), dispose(), fragment(), onEnter?(), onExit?() }` — the lifecycle hooks are optional and hosts call them via `built.onEnter && built.onEnter()`. **Ambience is `main.js`'s job**: the module's `ambience` recipe (and `mood`) is the single source of truth, started on enter and stopped on exit centrally — koans never call `startAmbience`/`stopAmbience` themselves. `registry.js` lazy-loads staged cases; if a case ever lacked a loader it would fall back to `default-case.js` (still the safety net, now covered by a direct test since every case has its own diorama). All 49 cases are staged, case 49 (Amban's addendum) included — it is the closing "book at rest" scene (pond + koi, birds, the path, and a red torii gate as the seal — the same gate the intro opens on, so the reader leaves by the door they entered). Case text comes from the generated `src/koans/text/mumonkan.js` — never hand-edit it.
- **The spine** (`src/spine.js`): the book's actual reading order — preface, the forty-nine in id order, afterword — is a list of slugs, not `CASES`; `neighborSlug` walks it for paging and the arrow keys, and it's the one place that knows front/back matter sit either side of the numbers. It is the only walk: it stops at both ends, because an arrow that wrapped would lose the reader their place. (There was a `nextInLoop` beside it that wrapped past the afterword back to the preface, for the hands-free reading that turned its own pages; that reading is gone — see the look, below.) **Matter pages** (`src/koans/matter/preface.js`, `afterword.js`) are koan-shaped modules that differ from a case only in `id: null`, which turns off the numeral seal. Both render `buildHub()` — the title screen's world — with pieces switched off, and each passes its **own three seeds** (`seed` / `groundSeed` / `pathSeed`, a named `SEEDS` constant at the top of each file) so the three scenes are different land rather than the same picture with a prop missing. The title screen's three are fixed by the intro dolly (`intro_rails.js` is hand-aimed at the gate on that road). The afterword *derives* which scatter tree its Buddha sits under from `built.trees` rather than storing a coordinate — it held a copy of one once, and the day a seed changed the tree moved and the meditator sat in open grass with nothing failing. `node scripts/dev/hub-trees.js` prints all three scenes' trees and where the mat landed — they are read, marked and narrated exactly like a case otherwise, and they sit in the contents as the first and last rows, without numbers. `registry.js` keys them by slug in their own `MATTER_LOADERS` table, separate from the numeric `LOADERS`. Their text is generated by `scripts/build-text.js` from a second, independent input, `local/mumonkan-front-and-back-matter.md`, into `src/koans/text/matter.js` — `mumonkan.js` and its 147 narration bakes are never touched by that path; the matter pages have their own five, keyed by slug (`preface:verse`) rather than by case number, bringing the book's narration to 154 units. The U+3000 ideographic space in `local/mumonkan-front-and-back-matter.md` marks verse structurally: `parse-matter.js` splits on it and strips it, so no indent ever reaches the page — verse is a labelled section here exactly as it is in a case.
- **The look** (the eye in the stage toolbar, `main.js`): the text panel steps aside, the diorama takes the whole window and the camera drifts. It is a *view*, not a mode — the reader is still in whatever page they were on — and deliberately not a reading: it starts no narration. A `.gg-look-bar` in the **top-left** corner carries the look's own controls — leave (↺), back, forward, "Read aloud" — opposite the stage tools on the right, which are settings; this corner is what you *do* to the book. It stays visible and in place wherever the look is on, the Contents included, and greys out what cannot act rather than hiding it, so nothing moves under the cursor. The read button calls the same `toggleReadAll()` as the panel's, so either one stops what the other started. **A read-aloud always ends at the end of its page** and never turns over — the book used to read itself page after page from the eye, and that is gone. The title card (`page_card.js`) is shown only in the look and only by the two things that give it something to say: a page turn, and a reading starting. `stageOnly()` derives the layout from the look *or* a sit, so leaving a sit never yanks the panel back over the look.
- **The kit** (`src/kit/`): procedural builders (monk, gate, flag, quadruped, lantern…) shared by all cases. The reuse rule is absolute — behaviors (hover ruffle, bell strike) live **in the kit components**, not in individual cases, so they travel wherever the component appears. Scene assembly goes through `composeWorld` (ground + mountains + forest + seeded scatter with keepouts).
- **Render** (`src/render/`): toon ramp + inverted-hull outlines, fog-to-paper, post spine (`post.js`) with depth ink / tone quantisation / paper grain, ink dissolve for every transition (`dissolve.js`), `freeze.js` holds the outgoing frame during cuts. No shadow maps — blob washes only. **The toon ramp is not what ships.** The kit builds every lit surface as a `MeshToonMaterial`, but the workbench's `toon` flag defaults to *false* (`debug.js`), so at runtime each one is rebuilt as a plain Lambert by `plainMaterial()` in `toon.js` and the reader never sees banding. The ramp's top texel covers every normal within ~71° of a light, so anything that renders raw toon materials — a preview page, a shot — turns a rounded low-poly form into a two-tone cut-out. `plainMaterial` is shared by the workbench and the model viewer for that reason; the list of properties it has been caught dropping (emissive, visible, map, alphaTest) is in its comment, and `keepMaterial` marks the meshes it must never touch.
- **Audio** (`src/audio/`): ambience and bells are fully procedural Web Audio, no samples. Pattern: pure **param tables** (e.g. `windParams`, `bellPartials`) are unit-tested; node builders are browser-only. **Narration is the one exception to "no samples"** — all 154 sections across the 49 cases and the two matter pages are pre-baked mp3 (see below). Playback is through an `<audio>` element outside the Web Audio graph, which is why `audio.duck()` ducks only the ambience bed. Runtime lookup is manifest-driven and degrades to silence: a section with nothing baked is a genuine no-op, never a stuck highlight, so a partial bake is a safe state.
- **Spatial audio** (`src/audio/spatial.js`): a pure `spatialFor(source, listener)` returns `{ d, pan, gain, tone, wet }`; a browser-only `makeSpatialBus` wires those numbers into a panner/filter/send. The camera is the listener — `src/camera_listener.js` converts its world matrix into the plain vectors the engine wants, which is why `engine.js` itself never imports THREE. Every one-shot takes an optional `at`; leaving it off reproduces the old unplaced behaviour, which is how roughly sixty call sites migrated one at a time instead of all at once. **The trap worth knowing:** reading `.position` on an object nested under its own group returns a LOCAL position — finite, plausible-looking, and wrong, panning the sound to the wrong side of the scene with nothing failing. Five such traps turned up in the migration; the fix is `getWorldPosition` into a module-level scratch `Vector3`, never `.position` read directly, wherever the sounding object is nested. `voicesDry`/`voicesWet` carry every diorama one-shot so `hushVoices()` can close a still-ringing sound at a page turn; the sit bell, narration's punctuation chimes, and the drift layer's far bell deliberately route around that pair, because they belong to the reader or the book, not the scene, and must not go quiet just because the page turned. The room is 1.8s now, not five — distance is what decides how *wet* a sound sits, not the room itself. Hidden pages pause on `visibilitychange`, never `blur` (alt-tabbing to a second monitor must not silence a page still on screen), fading master before suspending the context; a running sitting suppresses that pause so the closing bell still rings on time.
- **Routing** (`src/router.js`): deep links, one invariant — **the URL always names what's on screen**. `parseRoute`/`hashFor` are pure and Node-testable; `makeRouter` is the browser half (`initial()`, `set(route, { replace } = {})`, `dispose()`), wired into five points in `main.js` (boot, `buildKoan`, `exit()`, `onRoute`, `currentRoute`). Anything that calls `enter`/`exit` or changes `mode` must keep the URL in sync with it.
- **The staging net** (`tests/staging.test.js`): builds *every* staged case and holds all of them to the module contract at once — slug/accent/ambience shape, no non-finite transforms, taps safe before `setCamera` and with no audio engine, debug-panel-shaped fragments, the <150 draw budget, and that each case's accent projects inside its own home frame. Add a new case and it is covered automatically. Deliberate deviations (case 28's night page, the three cases with no drift, the legacy silent-on-touch list) are named constants at the top of that file with their reasons — read those before "fixing" one. Bespoke per-case tests are still the right tool for cases with real logic.
- **Testable-state pattern:** logic that tests need is split from DOM/WebGL glue — `menu_state.js` vs `menu.js`, `scroll_state.js` vs `scroll.js`, param tables vs node builders. Tests run in plain Node with no browser; keep new logic on the testable side of that line.
- **Look-dev harnesses:** `dev/lookdev.html` and `dev/kit-preview.html` for iterating on the art and kit pieces in isolation. `model-viewer.html` (repo root) is the standalone model viewer: every kit model single-view or as a gallery grid with per-model ok/needs-work notes (markdown export), plus hot reload — edit any file in the kit's import graph and the view rebuilds in ~1s. It renders the **shipped** shading (`shading.js` — see the Render note above) plus two dim tinted fill lights of its own (`lights.js`, L to toggle) for the far side of an orbit; `dev/model-shot.html?mode=toon` uses both, so a shot and the viewer always agree. Its roster lives in `src/modelviewer/roster.js` and is shared with `dev/model-shot.html`, so a new kit model is registered ONCE there and both the viewer and `shot.js --model` pick it up. `dev/bell-audition.html` is the same idea for the bonshō: ring it live and dial size and ring length, the hum/body/clang/shimmer macros (each multiplies ON TOP of the active preset's own exact baseline — 1 is unchanged), the mallet's two transient components (a low beam thump and a high ping, the ping with its own frequency control) and the reverb mix; an A/B toggle swaps the named-mode partials against named+shimmer on the same preset so the shimmer cluster's own contribution can be heard alone; hand/temple/great are the three shipped presets, live-edited independently rather than sharing one state (that used to be a bug — see the file's own comment); "print all three presets" dumps what the sliders currently PRODUCE as pasteable `ampMult` arrays, not where they sat. Frank intends to expand it; two gaps are the likely next ask — the macros band by mode INDEX, so there is no per-mode control, and the shimmer cluster is a fixed ratio table that scaling can louden or quiet but not reshape.

## Style guardrails (from the design doc)

- One accent hue per koan against monochrome ink + paper; fog dissolves everything before any horizon.
- **Nothing lit is painted at `INK`.** The toon ramp multiplies by 0.31/0.63/1.0, so at INK the three bands land on levels 9/19/30 — invisible, and every monk, torii and pole painted that way was a flat cut-out. Lit surfaces take `INK_LIT` (`wash(0.80)`, bands 22/46/73); raw `INK` is reserved for genuine voids — a cave throat, a doorway at night — drawn unlit with `MeshBasicMaterial`, where there is no shading to lose.
- Audio is minimal and chill: no singing bowl, no crickets. Bells, wind, quiet knocks are the palette. Nothing loud by default.
- Sensitive cases (3, 5, 14, 41) are handled through ink metaphor, never literal harm.
- Budgets: < 150 draw calls per scene, whole app ~1.5 MB gzipped, no downloaded assets. The baked narration (~35 MB of mp3 in `audio/narration/`, all 154 units) is outside this budget: it is lazy-loaded per case, never bundled, so it costs nothing at first load.
