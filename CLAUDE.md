# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive sumi-e reading of the Mumonkan (The Gateless Gate) in the browser: all 49 koan cases staged as small low-poly ink-painting dioramas, with text, narration, ambience, and a meditation timer. It is an **interactive book, not a game** — dioramas are ambient scenes; touch responses are optional delights, never gates.

The design doc at `docs/gateless-gate-design-doc.md` is authoritative; its dated revision notes **override** anything they contradict elsewhere in the doc. Milestone plans/specs live in `docs/superpowers/`.

## Commands

- Run: `npx -y http-server -p 8105 -c-1 .` then visit http://localhost:8105 — **no build step**; ES modules are served directly and Three.js is vendored in `lib/` (version in `lib/THREE_VERSION.txt`).
- Test all: `npm test` (runs `node --test` over `tests/`, Node 20+)
- Test one file: `node --test tests/k29.test.js`
- Regenerate the whole-book Markdown at the repo root: `npm run book` (`node scripts/build-book.js`) — writes `THE-GATELESS-GATE.md` from the generated text modules, so run `build-text.js` first if the source changed. `tests/book-md.test.js` fails if the committed file is stale.
- Regenerate koan text after editing `local/gateless-gate.txt`: `node scripts/build-text.js` (writes `src/koans/text/mumonkan.js`; the same run also parses `local/mumonkan-front-and-back-matter.md` into `src/koans/text/matter.js` and exits 1 if that second file is missing — it's required, not optional).
- Re-bake narration after a text change: `node scripts/build-narration.js` — only units whose text/voice/preset hash changed are regenerated, so this is normally a few files and a few cents. Needs a Gemini key in `local/gemini-key.txt` or `GEMINI_API_KEY` (the live provider is Gemini — see `PROVIDER` in `scripts/lib/narration-voice.js`; the OpenAI path remains for the audition bake-off). `--dry-run` shows what would bake without spending; `--case N` — or a matter-page slug such as `preface` — scopes it, and an unrecognised value is a hard error, never a silent fall-through to baking the whole book. Voice and delivery live in `scripts/lib/narration-voice.js`; `scripts/narration-audition.js` is the bake-off for changing them.
- Audit a bake for bad takes (no API cost): `node scripts/check-narration.js` (duration vs character count) and `node scripts/check-narration-wps.js` (speaking pace, crediting pauses). They normalise differently, so run both. Neither catches a same-length garble — that still needs ears.
- Screenshots while the preview panel is hidden: `node scripts/dev/shot-server.js` (port 8106; workspace launch config `gate-shots`), then POST a `canvas.toDataURL(...)` string to `http://localhost:8106/<name>` — files land in `shots/` (gitignored).

`local/` is gitignored — it holds the source text and Frank's local notes; don't assume its contents exist in a fresh clone.

## Headless driving

`window.gate` exposes hooks for driving the app without a visible page: `step(n)`, `state()`, `enter(slug)`, `exit()`, `menu(open?)`, `skipIntro()`, `dissolve('in'|'out', s?)`, `sit(min)`, `endSit()`, `markRead(slug)`, `markSat(slug)`, `setSound(on)`, `look(on?)`, `readAloud()`, `auto(on?)`. `state().reading` reports `{ look, all, slug }` — `look` is the text-aside view, `all` whether the page is being read aloud. The look never starts a reading, and a reading stops at the end of its own page rather than turning over.

Caveat: the hidden preview panel pauses `requestAnimationFrame`, so `await gate.enter(...)` hangs — dissolves only advance inside `step()`. Fire the call, then `step(60)` once per await stage (`loadKoan` → dissolveOut → dissolveIn), yielding between batches so microtasks flush.

## Architecture

- **Determinism rule:** seeded noise everywhere (`src/util/noise.js`), **no `Math.random` outside `src/audio/**`** — same steps, same state. Audio is exempt because noise buffers don't affect sim state.
- **Koan modules** (`src/koans/kN.js`): each default-exports `{ id, slug, title, accent, tier, text, ambience, mood?, camera?, build(ctx) }`. `build` returns `{ scene, update(dt, simTime), dispose(), fragment(), setCamera(), onEnter?(), onExit?() }`. **Ambience is `main.js`'s job**: the module's `ambience` recipe (and `mood`) is the single source of truth, started on enter and stopped on exit centrally — koans never call `startAmbience`/`stopAmbience` themselves. `registry.js` lazy-loads staged cases (`default-case.js` is the still-tested safety net). All 49 cases are staged; case 49 (Amban's addendum) is the closing "book at rest" scene, sealed by the same red torii the intro opens on. Case text comes from the generated `src/koans/text/mumonkan.js` — never hand-edit it.
- **The spine** (`src/spine.js`): the reading order — preface, the forty-nine in id order, afterword — as a list of slugs. `neighborSlug` walks it for paging and the arrow keys and **stops at both ends**; `loopNextSlug` beside it wraps afterword → preface, but it exists ONLY for auto mode (below) — the arrows never wrap. **Matter pages** (`src/koans/matter/preface.js`, `afterword.js`) are koan-shaped modules with `id: null` (no numeral seal). The **preface stages its own diorama** — the arriving road forks into two arms ("thousands of roads enter it"), a bonshō and a flag stand either side of the split, and no gate exists anywhere in it (tests/matter.test.js pins the fork). The **afterword** renders `buildHub()` — the title screen's world — with its own `SEEDS` so the two hub scenes are different land; the title screen's are fixed by the intro dolly (`intro_rails.js`). The afterword *derives* its Buddha's tree from `built.trees` rather than storing a coordinate — a stored copy once went stale when a seed changed and the meditator sat in open grass with nothing failing. `node scripts/dev/hub-trees.js` prints both hub scenes' trees. Matter text is generated from `local/mumonkan-front-and-back-matter.md` into `src/koans/text/matter.js` — a separate path that never touches `mumonkan.js` or its 147 case bakes; the matter pages' own seven units (keyed by slug, e.g. `preface:verse`) bring the narration to 154. The U+3000 ideographic space in the matter source marks verse structurally; `parse-matter.js` splits on it and strips it.
- **The look** (the eye in the stage toolbar, `main.js`): the text panel steps aside, the diorama takes the whole window, the camera drifts. A *view*, not a mode — the reader stays on their page — and it starts no narration. The `.gg-look-bar` (top-left) carries the look's own controls — leave, back, forward, read aloud — and greys out what cannot act rather than hiding it. **A read-aloud always ends at the end of its page** and never turns over. **Auto mode is the one deliberate exception**: the look bar's labelled switch ("Read the whole book, page after page") reads, pauses a few seconds, turns, and reads on — wrapping via `loopNextSlug` until switched off. A different promise made by a different, labelled switch; the read-aloud rule stands. The title card (`page_card.js`) shows only in the look, only on a page turn or a reading starting. `stageOnly()` derives layout from the look *or* a sit, so leaving a sit never yanks the panel back over the look.
- **The kit** (`src/kit/`): procedural builders (monk, gate, flag, quadruped, lantern…) shared by all cases. The reuse rule is absolute — behaviors (hover ruffle, bell strike) live **in the kit components**, not in individual cases. Scene assembly goes through `composeWorld` (ground + mountains + forest + seeded scatter with keepouts). Prefer keepouts by live reference — `{ at: object, r }` — over copied coordinates: a moved prop once left its keepout guarding empty grass with nothing failing.
- **Shared helpers — use them, don't re-declare:** `src/util/math.js` (`clamp01`, `clamp`, `smoothstep`); `tapMeshes` in `src/kit/pick.js` for collecting tappable meshes; `wrapPi`/`bearing` exported beside `faceMonk` in `src/kit/monk.js` (the facing convention: bodies front local +z, a heading ψ points along `(sin ψ, cos ψ)` — hand-rolled variants have shipped quarter-turn bugs); tests build their ctx from `tests/helpers/fake-ctx.js`. In `update(dt, simTime)`, guard before simTime reaches any transform: `clock = Number.isFinite(simTime) ? simTime : clock + (dt || 0)`.
- **Comments are records** here — they quote decisions and past bugs. When retuning a number by hand, update the prose that presents it as solved or derived; a cleanup pass found six kit headers contradicting their own code after "tweaks" commits did exactly this.
- **Render** (`src/render/`): toon ramp + inverted-hull outlines, fog-to-paper, post spine (`post.js`), ink dissolve for every transition (`dissolve.js`), `freeze.js` holds the outgoing frame during cuts. Shadows: real shadow maps ARE the shipped look since v6 (`shadows` defaults true in the workbench; `makeLights` carries the sun's shadow camera — ±15 frustum, 3072 map, ~100 texels/unit). The per-case `makeBlobShadow` washes were the original design; they were removed entirely on Frank's call once the maps shipped — every scene was building washes the workbench immediately hid. **The toon ramp is not what ships**: the workbench's `toon` flag defaults to *false* (`debug.js`), so every lit surface is rebuilt as a plain Lambert by `plainMaterial()` in `toon.js`. Anything rendering raw toon materials (a preview page, a shot) turns rounded low-poly forms into two-tone cut-outs — the ramp's top texel covers every normal within ~71° of a light. `plainMaterial`'s comment lists the properties it has been caught dropping; `keepMaterial` marks meshes it must never touch.
- **Audio** (`src/audio/`): ambience and bells are fully procedural Web Audio, no samples. Pure **param tables** are unit-tested; node builders are browser-only. Recipes may flavor the wind (`wind:0.18:pine`), name a `rain` layer (case 34), or carry a `snow` token that swaps the reverb to the darker snow room (case 41). **Narration is the one exception to "no samples"** — all 154 sections are pre-baked mp3, played through an `<audio>` element outside the Web Audio graph (which is why `audio.duck()` ducks only the ambience bed). Runtime lookup is manifest-driven and degrades to silence: a partial bake is a safe state, never a stuck highlight.
- **Spatial audio** (`src/audio/spatial.js`): pure `spatialFor(source, listener)` returns `{ d, pan, gain, tone, wet }`; browser-only `makeSpatialBus` wires the nodes. The camera is the listener via `src/camera_listener.js` (plain vectors — `engine.js` never imports THREE). Every one-shot takes an optional `at`. **The trap worth knowing:** `.position` on an object nested under a group is a LOCAL position — finite, plausible, and wrong; use `getWorldPosition` into a module-level scratch `Vector3`. `voicesDry`/`voicesWet` carry diorama one-shots so `hushVoices()` can close them at a page turn; the sit bell, narration's chimes, and the drift layer's far bell deliberately route around that pair — they belong to the reader or the book, not the scene. Hidden pages pause on `visibilitychange`, never `blur` (alt-tabbing must not silence a page still on screen); a running sitting suppresses the pause so the closing bell rings on time.
- **Routing** (`src/router.js`): deep links, one invariant — **the URL always names what's on screen**. `parseRoute`/`hashFor` are pure and Node-testable; `makeRouter` is the browser half, wired into five points in `main.js`. Anything that calls `enter`/`exit` or changes `mode` must keep the URL in sync.
- **The staging net** (`tests/staging.test.js`): builds *every* staged case and holds all of them to the module contract at once — shape, no non-finite transforms, taps safe before `setCamera` and with no audio engine, finite-scalar fragments, the <150 draw budget, the accent in its home frame, and that every interaction reaches the audio engine. A new case is covered automatically. Deliberate deviations are named constants at the top of that file with their reasons — read those before "fixing" one. Bespoke per-case tests remain the right tool for cases with real logic.
- **Testable-state pattern:** logic that tests need is split from DOM/WebGL glue — `menu_state.js` vs `menu.js`, `scroll_state.js` vs `scroll.js`, param tables vs node builders. Tests run in plain Node with no browser; keep new logic on the testable side of that line.
- **Look-dev harnesses:** `dev/lookdev.html` and `dev/kit-preview.html` iterate on art and kit pieces in isolation. `dev/model-viewer.html` is the standalone viewer — every kit model, gallery grid, per-model notes, hot reload (~1s) — rendering the **shipped** shading plus its own two dim fill lights (L to toggle); `dev/model-shot.html?mode=toon` matches it. The roster lives in `src/modelviewer/roster.js`, shared with `model-shot.html`: register a new kit model ONCE there and viewer and `shot.js --model` both pick it up. `dev/bell-audition.html` does the same for the bonshō (live macros over the three shipped presets; "print all three presets" dumps pasteable `ampMult` arrays); `dev/hanging-audition.html` for the hanging chimes. Details and known gaps live in each file's own header comments.

## Style guardrails (from the design doc)

- One accent hue per koan against monochrome ink + paper; fog dissolves everything before any horizon.
- **Nothing lit is painted at `INK`.** The toon ramp multiplies by 0.31/0.63/1.0, so at INK the bands land at levels 9/19/30 — invisible. Lit surfaces take `INK_LIT` (`wash(0.80)`); raw `INK` is reserved for genuine voids — a cave throat, a doorway at night — drawn unlit with `MeshBasicMaterial`, where there is no shading to lose.
- Audio is minimal and chill: no singing bowl, no crickets. Bells, wind, quiet knocks are the palette. Nothing loud by default.
- Sensitive cases (3, 5, 14, 41) are handled through ink metaphor, never literal harm.
- Budgets: < 150 draw calls per scene, whole app ~1.5 MB gzipped, no downloaded assets. The baked narration (~35 MB of mp3, all 154 units) sits outside this budget: lazy-loaded per case, never bundled.
